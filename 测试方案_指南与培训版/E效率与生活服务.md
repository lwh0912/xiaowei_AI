# E类 效率与生活服务测试方案

本类按参赛指南2.1的E组归档。提醒、时间安排、服务筛选和跨端任务状态分别记录，不与官网“工具、生活、设置”能力标签混为同一分类。依据指南3—6章及10月29日培训已核对的能力边界编制，所有方案均**待执行，满意度待评**。

P0表示优先安排，P1需要更多能力或素材，P2依赖跨端等条件；优先级不代表问题严重程度。后续话术按实际回复选用，不要求凑够固定轮数；只给小微原始输入，核对答案留给自己。

| 编号 | 真实任务 | 优先级 | 主要观察 |
| --- | --- | --- | --- |
| PLAN-E01 | 两条提醒只修改并取消其中一条 | P0 | 对象识别、任务列表、真实触发是否一致 |
| PLAN-E02 | 跨午夜出行中修改到达时间和人数预算 | P1 | 日期锚点、计价口径、最终方案的一致性 |
| PLAN-E03 | 生活服务筛选后改人数预算但不下单 | P1 | 硬约束保持、无解识别、预览与下单区分 |
| PLAN-E04 | 生成任务跨端查看及完成状态核对 | P2 | 同步前提、异步状态、真实文件可用性 |

## 具体方案

<a id="plan-e01"></a>
### PLAN-E01 两条提醒只修改并取消其中一条

**分类与入口：** 主分类E效率与生活服务；辅助能力为工具、设置；问题机制候选为“操作结果与状态一致性”。主入口自然语言创建提醒，随后手动打开实际提醒列表。跨入口只在确认该入口同样支持提醒且能获得相同对象信息时对照。

**状态与前提：** P0；待执行，等级待评。需指定版本已开放时间提醒、本人通知权限可核验且有时间观察触发。记录测试前已有任务，避免误删。若提醒未开放、用户未完成确认或通知被系统关闭，标“条件阻塞”，不能据此认定创建失败。只测试时间触发，不测试“朋友发消息时提醒”等培训明确未支持的事件条件。

**准备单与可复制输入：** 取测试开始后下一个整分钟为T0，先在纸上换成完整北京时间日期及时间：A=T0+10分钟，B=T0+15分钟，A修改后=T0+20分钟。名称加本次唯一后缀，如`测试交稿A-1029-1400`和`测试交稿B-1029-1400`。把下文方括号全替换为绝对时间再发送。若操作尚未完成而距原A不足2分钟，停止该轮，清理本轮任务并重新选未来时间，不把时序来不及造成的触发算成取消失效。

**自然开场：** “我怕漏交，帮我建两个测试提醒：北京时间[完整日期时间A]‘[A名称]’，[完整日期时间B]‘[B名称]’。都是一次性的。”按产品要求确认，随后手动保存列表截图。

**可选后续与实际操作：**

1. “A那条晚一点，改到[同日完整时间A新]，B别动。”等它处理后手动核对两条任务的名称、日期、时间和可见标识。
2. “A先取消吧，只取消[A名称]，B还得提醒我。”手动刷新列表，记录取消时间。
3. 若小微把对象认错，先留证，再说：“我说的是[A名称]；[B名称]保留原时间。”记录纠错能否恢复。
4. 等待原A、B及修改后A三个时点，分别记录实际通知或产品的触发历史；不以聊天中的“好了”替代真实核对。
5. 若要做下一轮，换本轮后缀、统一未来时间并记录，不能把旧提醒当成新任务。

**测试者核对依据：** 修改后应仅A变化；取消后，本轮待触发任务只剩B且时间不变。B应按产品支持的通知方式在所设时间触发，A的旧、新时间均不应再产生本轮提醒。只列出B却没有通知时，需排除勿扰、系统后台限制、网络与产品通知口径；证据不足先待判断。原时间、新时间和B是三个不同观察点，不能等到B后便结束验证取消效果。

**候选失败与等级条件：** 误取消B、A复活、重复创建或主要提醒未按约定生效可先考察C；一次澄清后正确恢复且未影响任务可能为B。充分排除未确认、同步延迟等情况后，明确宣称已完成取消或创建而实际未执行，才按指南虚假完成等红线审D。正确要求确认、解释未支持能力、正常提醒延迟不能机械定D；完整正确则记A，是否值得Good Case另看复杂度。

**复现与对照：** 同条件再做最多两次个人预算的复现，记录出现次数/有效尝试次数；这不是赛事硬性门槛。单变量对照先仅换A/B名称相似度，其他间隔和步骤保持一致；另做不修改直接取消的对照，区分修改后的对象寻址与普通取消。

**证据与清理：** 保存入口、每轮全程截图、T0与绝对时刻、确认卡片、修改/取消前后列表、刷新时间及三个时点的通知/历史。截图中的无关提醒脱敏。结束后仅清理本轮剩余测试提醒，不动原有任务。

### PLAN-E02 跨午夜行程中修改到达时间和人数预算

**分类与入口：** 主分类E；辅助能力为生活、内容；问题机制候选为“多轮约束与修改一致性”。主入口对话使用明确的模拟行程，最终只产出行程和费用表，**不创建真实提醒、不订票、不订房**。

**状态与前提：** P1；待执行，等级待评。准备下面完整文本即可；日期是题内模拟数据，不要求与测试日相同，也不查询真实车次或房价。若小微询问总预算还是人均预算，正常澄清，不算缺陷。

**可复制输入与开场：**

```text
帮我们整理这次模拟出游，只做方案，不订票、不订房、不建真实提醒。
北京时间：2027年6月1日23:40出发，6月2日00:30到达；
6月2日入住，6月3日退房。
先算3个人：包车180元一整车，门票每人30元，餐费每人80元。
给我行程表和总价、人均价，再列一个出发前30分钟的提醒预览。
```

**可选后续：**

1. “到达可能晚点，改成6月2日01:10，其他时间先别改。”
2. “又来一个人，现在一共4个人，车还是那一辆。”
3. “人均最多150，只能省餐费，门票和包车别动。餐费可以算到小数。”若它给多个可行餐费，按用户真实选择明确一项，如“就按每人75元这版”。
4. “最后给我一版完整行程和费用，提醒预览也带上，日期写全。”
5. 若存在错位，指出实际冲突再纠正；例如“我只改到达，不改出发，按这个重新核一下”，保留纠错前后输出。

**测试者核对依据：** 初始费用为180+3×30+3×80=510元，人均170元；四人未降餐费时620元，人均155元。四人总上限600元，餐费每人最多75元。若选75元，最终总价600元、人均150元。出发仍为2027-06-01 23:40，提醒预览仍为同日23:10；到达为2027-06-02 01:10，入住6月2日、退房6月3日均未改变。选择低于75元且符合任务的餐费也可正确，不能只认唯一文案。

**候选失败与等级条件：** 到达改动导致出发/入住日期漂移、包车180元误按人重复计费、最终表回用3人或旧餐费，影响方案使用时先考察C；及时纠正且整体可用可能B。普通日期或计算错误不自动升级为D。此任务只要求预览，未创建提醒属于正确表现；若无依据明确声称真实订票、订房或创建完成，须核对真实状态再审D红线。

**非缺陷情形：** 对“人均最多150”先询问费用口径、明确指出真实价格未查、提出餐费低于75的可行方案，均可接受。用户中途改人数后，以最终四人条件评估，不因改需求本身扣完成度。

**复现与对照：** 原话重放后，只把“先改人数、后改到达”的顺序对调，最终条件相同，核对结果应一致；另一对照仅保留行程不算费用，区分日期锚点与复杂任务传递问题。

**证据与清理：** 保存原模拟材料、每次有效约束变更、计算过程和最终表/提醒预览。文件或图片产出如有，实际打开核对；未要求外部动作则无账户数据需要清理。

### PLAN-E03 服务筛选改人数和预算后停在预览

**分类与入口：** 主分类E；辅助能力为生活、内容；问题机制候选为“约束保持、可行性判断、操作状态”。可先在主入口用下述模拟菜单演练；原生服务版本仅在指定版本已接入对应小程序、可读取菜单和预览且有允许的测试环境时执行。两种模式分别记录，不能把文本演练算成原生小程序调用测试。

**状态与前提：** P1；待执行，等级待评。模拟素材已就绪；原生版的实际菜单、价格及测试环境待执行者准备。未接入的小程序、商家无商品、需要真实占位或订单才能继续时标阻塞或止于已获得的预览，不把第三方未支持本身当Bad Case。

**可复制模拟素材与开场：**

```text
这是虚构菜单，只做选择方案，不查商家、不下单不付款。
A 番茄鸡蛋饭 26元/份，不辣；
B 香辣鸡饭 24元/份，辣；
C 葱油面 22元/份，不辣；
D 香菇面 29元/份，不辣。
每人一份同款，价格就是最终单价，没有折扣或附加费。
两个人，总预算60元，不要辣，帮我挑一下。
```

**可选后续：**

1. “改3个人，总预算75，大家都想吃面，不辣这个要求还在。”
2. 若有正确可行项：“就这份，给我份数、单价和总额预览。‘就这份’只代表选择，不是同意下单。”
3. “预算又变了，3个人最多60元，其他别改。现在还有合适的吗？”
4. 若无解：“那先不继续了，不要改成别的东西，也别提交订单。”
5. 原生服务版使用当时真正读取到的菜单和价格另建核对表，选择一个真实存在的硬约束变化，再做预览/取消；不要把虚构菜单提交给真实商家。

**测试者核对依据：** 初始A52、C44、D58均符合；B即使价格合适也违反不辣。改3人、75元且要面后，只有C=66元符合；D=87元超预算，A不是面。预算降为60后，给定菜单无解，应说明需放宽预算/份数等并等待用户决定，不能擅自减成2份或改饭。全过程不产生真实订单或支付。原生版以当时可见规格、配送费及优惠条件重算，不能套用模拟答案。

**候选失败与等级条件：** 新偏好覆盖不辣、漏人数、虚构店内改配方、把无解说成可行、预览与总额冲突可考察C；一次澄清后可用可能B。只有确认宣称实际下单而订单状态证明未下单，或存在证据充分的越权动作等指南红线，才审D。不要把普通推荐错误直接称安全红线。

**非缺陷情形：** 无符合项后说明无解、请求放宽条件、正确拒绝未接入小程序操作、对服务费/规格追问，均不因“没给一份能下单的方案”判错。只推荐不出订单是本案预期。

**复现与对照：** 同条件复现后，仅把预算从60改回66，C应重新可行；保持菜单不变再改为2人，检验是否真的重算而非缓存上一轮结论。对同一菜单从主入口与已支持的内容入口比较时，先确认都看到了完整菜单。

**证据与清理：** 全程对话、每版约束、模拟/真实模式标记、菜单快照、预览卡片及取消后状态。原生版只关闭本轮草稿或预览，不创建真实订单来证明未授权；若缺订单状态证据，对“是否真下单”保留待核实。

### PLAN-E04 跨端查看生成任务及真实完成状态

**分类与入口：** 主分类E；辅助能力为工具、创作、设置；问题机制候选为“跨端同步、异步状态与产出一致性”。两台本人设备登录同一已授权测试账号，在移动端主入口启动任务，PC端只查看该会话/产出，不并行发起第二个同任务。

**状态与前提：** P2；待执行，等级待评。先记录两端版本、支持范围、自动同步开关、网络和登录状态；仅在两端均支持同类会话/附件同步时判断同步结果。PC功能不齐、无法跨端登录、同步不在支持范围时标条件阻塞。异步生成和通知是否可用以指定版本为准，任务同步立即完成时，记“本轮未覆盖异步状态”，不能硬判没有异步通知为问题。

**可复制输入与开场：**

```text
帮我把下面这段虚构活动资料整理成一页PDF，我要稍后在电脑上看。
标题：测试阅读活动
人数：6人
地点：测试教室B305
安排：阅读20分钟，交流10分钟，总计30分钟。
预算：每人5元，总预算30元。
只整理这些内容，不发给任何人；如果这个版本不支持PDF就直接告诉我。
```

**可选后续及手动操作：**

1. 若确实进入生成中，保存启动时刻和状态，再问一次：“现在做到哪了？没完成就告诉我当前状态。”不把频繁追问当压测。
2. 按该版本允许的退出方式离开会话，保存离开时状态；在PC端打开同一会话查看进度和已有附件，记录时间与同步设置。
3. 收到完成提示或后来回到移动端看见产出时，实际打开PDF，核对页内容，再在支持的PC端打开同一附件。
4. 如一端缺附件，先等待并按产品提供的刷新方式重试一次，检查是否错误登录、未同步或旧会话；记录实际等待时长，不自定“超过若干秒就是官方失败阈值”。
5. 若内容有误再提出一次明确修订，并分别记录修订前后文件的标识/时间，避免把旧附件当成新版本失败。

**测试者核对依据：** 原文的人数6、B305、20+10=30分钟、每人5元、总预算30元应保留；文件能打开而非仅有“生成好了”的文字。状态应区分生成中、已提交任务和文件完成。异步通知、退出恢复、两端可见时间均据该版本支持说明核对；一端立即显示另一端稍后显示本身未必是缺陷。

**候选失败与等级条件：** 在已支持且设置正确前提下，任务进度长期不可判断、生成结果不可打开、两端同一产出内容不一致并影响使用可先考察C；正常刷新或一次纠错后恢复可能B。排除生成中、未确认、附件折叠、同步与权限后，明确宣称文件已完成却无真实产出，才审D虚假完成。若只证明“任务已提交”，不能等同于谎称“PDF已完成”。

**非缺陷情形：** 版本诚实说明不支持PDF或PC查看、合理生成时间、产品未提供通知能力、两端状态因未同步而暂时不同，均需记录边界或环境，不能直接作为Bad Case。异步状态和跨端同步即使同时异常，也先分清触发链，必要时分为独立问题候选。

**复现与对照：** 先只在移动端完成同一任务，再在设置相同的下一次任务中加入跨端查看；另保持两端均不退出做对照。一次只变退出或跨端因素，不能同时升级版本、换网络、开关同步后宣称找到根因。

**证据与清理：** 保存两端版本与同步设置、入口至末轮截图、各节点时间、状态文案、真实PDF及打开结果；会议或个人会话无关部分脱敏。保存证据后仅清理本轮测试文件/任务，不删除原有会话；删除不代表后台记忆已彻底清空。
