# 小微AI助手分类测试方案

编制日期：2026-10-29。依据用户提供的《参赛指南》第2—6章，以及10月29日培训中已核对的投影片和提交表单。以初赛真实任务探索为主，同时保留决赛可用的数据；方案中的任务均未据此实际执行。

记录格式已按用户后来提供的[老师模板](../老师模板/README.md)更新。实际案例分别使用Bad/Good填写稿，报告使用报告稿，保留原字段和选项；本方案的探索方法不替代表单要求。

**采用指南A—F六类场景作为主目录，每类4个任务，共24个探索任务。** 每类先做一个适合自己的任务，再深入已观察到的问题。发现问题的数量、满意度及提交价值必须由实测决定；24不是赛事要求，也不是24个已发现缺陷。

## 一 分类规则

| 分类轴 | 如何使用 | 示例 |
| --- | --- | --- |
| 主场景 | 按指南2.1节A—F归档，一条实际发现只选一个主类 | F小工具创建 |
| 辅助能力 | 社交、内容、工具、生活、创作、设置，可多选 | 工具＋创作 |
| 实际入口 | 记录实际点击路径及提供的上下文 | 主入口→创建工具→打开工具页 |
| 问题机制 | 实测后按可观察表现填写Q1—Q7 | Q6修改工具后旧数据丢失 |
| 满意度 | 执行完成后按指南判断A/B/C/D | C档，主需求未满足 |
| 反馈有效性 | 单独判断是否适合作Bad Case；X仅用于筛除记录 | 正确解释未开放能力→不作为Bad Case |

**场景A类与满意度A档是两回事。** 辅助能力也不能替代场景分类。“工具能力”中的文件分析通常属于D，提醒属于E，生成交互工具属于F。

任务预先的分类便于找材料；实际发现应按出错环节修正主类。例如同一账单任务，识图错误归C；读数正确但最终拟稿回退旧金额可归A；生成账本修改后丢数据归F，其余分类保留为关联标签。跨能力会话保留完整任务链，不把同一发现重复填入多个分类。

P0是先做，P1是准备材料/核对能力后做，P2是条件合适再做；优先级不代表严重度、官方权重或预估命中率。首批六例仍受权限和素材约束，缺条件时换做另一类，不为覆盖而硬测。

按指南现有结构，初赛为六维度加权评分×50%＋问题库计价分×50%＋Good Case加分（最高10分）；最终细项以正式计分规则为准。本方案不设置“每类必须找到几条问题”的配额，而是为六维度准备可检查的证据：

| 评审维度 | 方案中的具体工作 | 报告里交代什么 |
| --- | --- | --- |
| 场景广度 | A—F起点＋可比的入口/条件变化 | 实际覆盖矩阵、阻塞和未测范围 |
| 深度挖掘 | 同一任务自然连续使用、修改后回归、跨环节核对 | 关键轮次、首次错误、纠错及复现；不为达到轮数硬聊 |
| 满意度准确性 | 独立核对答案、先排除无效反馈再分级 | B/C及C/D边界、D红线证据、非Bad Case原因 |
| 创新与复杂场景 | 多能力任务、F类交互工具、真实生活中的约束变化 | 为什么任务有价值，复杂性来自哪里 |
| 方法论与文档 | 同条件重放、单变量对照、机制归纳和问题去重 | 完整记录、已知规律与不能定位的部分 |
| 隐私与安全 | 限定输入/授权范围、草稿与动作区分、脱敏归档 | 数据来源、明确禁用条件、实际越界证据及最小化处理 |

问题库按类计价且同类只计一次，因此优先补齐代表性问题证据。正常但复杂的一次到位任务另留Good Case，不为满足某种等级比例改写结果。

## 四 一次任务怎样执行

1. **说明环境和真实需要。** 记录设备、微信/小微版本、时间及时区、网络、账号类别、入口路径、相关权限、记忆与同步开关。选择自己确实要完成的事，必要时把案例示例改成有明确来源的实际条件。
2. **先给原始材料。** 只发送案例中的输入材料和本轮要求，把核对答案留给自己。需要图片、文件或真实入口时，按前提准备；纯文字模拟不能证明图片、文件或微信原生能力正常。
3. **根据回复继续。** 等本轮结束再自然改条件、补材料或纠错。合理澄清正常回答；除案例明确标记的鲁棒性扰动外，没有出错时不虚构“你刚才错了”。A03的错误质疑是预先设计的扰动，不作为新事实修订，仍按原文核对；不能把它伪造为真实用户纠错经历。任务已完成可以结束，不为了五轮硬加话。
4. **核对任务状态和产出。** 区分拟稿、待确认、已提交异步任务、已生成和已执行。打开附件和工具；提醒看列表及实际触发；跨端看设置、账号与版本。生成中和短暂同步延迟不能直接证明失败。
5. **先保留原始证据，再复现。** 保存第一轮至末轮截图与操作链，再按同一条件尝试复现。个人建议额外做两次有效尝试；次数不是官方门槛或稳定性保证。执行前定义分母：错误素材、错误账号、人工中断等单列；满足前提后由产品卡住、无回复或崩溃造成的未完成，要保留为任务失败或待判断，不能因没到后续步骤而剔除。特定机制的复现统计与整项任务的完成结果分别记录，如“3次有效任务尝试，2次发生单位回退，另1次生成卡住未覆盖该机制”。
6. **只改一个因素做对照。** 例如把同内容图片改成文字、明确口语中的歧义、换入口但保持材料一致；保存对照上下文，不能用对照覆盖首次失败。
7. **按事实归档。** 写“在哪轮违背了哪条已明确的要求、造成什么影响”，再判有效性、满意度、主分类与问题机制。未完成的步骤标明未测。

发消息、发朋友圈、支付、下单、通话和账户设置默认只做到草稿或预览。需要真实创建的测试提醒和工具在案例中列明，使用自有数据并保留清理前证据；本方案文本本身不授权操作真实社交对象或发生交易。

语音可作为有条件的输入变体：先记录实际转写结果，再判断错误发生在语音识别还是后续理解。听一听等入口暂不编造覆盖，拥有实际需求和权限后可按同一方法补入。

每类先完成一个有判据的基线；再挑2—3个有实际问题或有真实复杂需求的任务纵向探索。例如C01账单读数→D类核对计算和版本→A类生成群消息→F类记录入账，逐段核对，不把四段结果计成四个独立问题。无异常时保留正常记录，复杂且一次到位才考虑Good Case。

## 六 问题机制与去重

沿用原项目Q1—Q7目录，避免重新造一套混淆标签。机制只能在实测后填写；不能从方案标题推断内部故障。

| 标签 | 可观察问题 | 主要候选任务 |
| --- | --- | --- |
| Q1 多轮约束与修改一致性 | 条件更新后旧值回流、未修改内容丢失、对象串线 | A01/A02、B01、D01 |
| Q2 来源依据与事实可靠性 | 编造引用、实体错配、新旧年份混用 | A03、B03、D02/D03/D04 |
| Q3 操作结果与状态一致性 | 草稿与发送混淆、取消未生效、口头状态与真实产出不符 | B02、E01/E04 |
| Q4 图片理解与编辑保真 | 识别错误、双图串用、修改非目标元素 | C01—C04 |
| Q5 文档覆盖与指令边界 | 漏末尾例外，把材料内指令当成用户授权 | A04、D02 |
| Q6 数据保存与工具修改 | 已有数据损坏、撤销或持久性错误 | F01—F03 |
| Q7 隐私约束与交互行为 | 忽视明确的信息使用限制、严重贬损等 | A02、B04；其他任务自然出现时记录 |

同一Q标签不等于同一缺陷；去重时比较触发条件、违反的有效需求、表现和最短复现路径。仅换人名/金额且同一机制复现，先关联主案例；不同任务链暴露了不同问题也可分别分析。最终提交粒度和问题库聚类以赛事口径为准，不承诺每个变体单独加分。

F04等工具计算错误须按实际表现归类：单位切换后沿用旧输入可关联Q1，保存修改损坏可关联Q6；独立公式错误可另记“其他/规则计算”，不能只因在小工具里发生就全部塞进Q6。各案例的观察方向只是候选，实际机制留到实测后判断。

现有[30例](../优化测试案例30例.md)、[六类能力60例](../六类能力测试案例/README.md)和[分类记录册](../BadCase与GoodCase分类记录.md)继续保留。这24例是结合培训范围重新组织的执行方案，与旧案例存在复用，不应把数量相加成114个独立任务或缺陷。已有实测候选继续引用原记录编号，补证据时不重建成新发现。

## 七 分级与提交判断

先排除无效反馈，再判断实际任务完成度。反馈有效性和满意度是两个字段；正确解释未支持能力可能按指南属于B档，但仍不作为Bad Case提交。

| 实测结果 | 处理 |
| --- | --- |
| 一次到位，明确约束都满足，真实产出可用 | A；复杂或新颖任务可用Good Case模板，普通问答不主推 |
| 核心办成，有可接受的小瑕疵或及时纠错 | B；老师本版Bad/Good均允许B，按实际瑕疵或复杂任务亮点选择，不重复报同一例，不保证加分 |
| 主要需求未满足、反复沟通或结果有实质缺陷 | C候选；说明具体需求和实际影响 |
| 充分证据命中指南4.4红线 | D；附具体红线、触发条件和原始证据 |
| 正确拒答、合理追问、友好性格、解释清楚的未支持、合理耗时、按最终改动办成 | 不作Bad Case；X为本地筛除标记，不是第五档 |
| 入口未开放、素材不足或无法观察真实结果 | 条件阻塞/待补证据；不预填满意度或缺陷 |

D档需重点核对：虚假完成、确定性编造、复读或纠错无效、任务失败无补救、安全泄露或贬损、该拒未拒。普通算错、图片轻微噪声、暂未见异步成品、猜中一处地点均不能单独证实红线；尤其要排除上下文已提供、任务仍在生成和范围限制。

每条提交按[老师模板](../老师模板/README.md)完整填写，不能只保留指南五项的简化摘要。Bad/Good一例一Issue，私密正文；平台标题保持默认`Bad Case`/`Good Case`，具体结论填总结字段，公开属性不放隐私。确认附件可读、CNB成功及小程序同步，不因延迟重复建Issue。

按老师本版，Bad只评最后30条、Good只评最后10条；优质Good确认后每条2分，最多5条封顶10分。这不是提交配额，末N条具体排序口径待官方确认。无效反馈不参与正向计分、也不倒扣，但计入分级准确性分母。真实提交后另记[提交台账](../老师模板/提交台账.md)，不擅自代参赛者勾选确认。

## 八 执行排期与完成标准

以下投入与数量均为个人建议。赛程按所给指南：11月1—5日体验，11月6—13日初赛；具体开放、截止时刻和正式计分以官方通知为准。

| 阶段 | 工作 | 留下的成果 |
| --- | --- | --- |
| 权限开放前 | 核对分类、准备素材/答案、建台账，不将其他模型结果当小微实测 | 可用素材清单、待开放条件 |
| 体验期前半段 | 确认环境，分批执行各类01，不超过实际可记录的量 | 至多6个基线记录及阻塞原因 |
| 体验期后半段 | 对出现的异常做同条件复现和单变量对照；正常复杂任务保留正例 | 主案例及变体关联、证据缺口 |
| 初赛前中段 | 按需求执行剩余任务，优先深挖独立问题，整理分级与去重 | 有事实依据的Bad/Good Case候选、阶段规律 |
| 初赛截止前至少一天 | 按正式渠道提交已核实材料，检查私密与脱敏、模板和同步 | 提交回执、附件清单、总结报告 |
| 初赛后至决赛 | 从真实会话积累分级样本，再按正式任务准备体系和程序 | 完整会话/标签/归因；四档与边界覆盖情况 |

单案可先安排15—30分钟，提醒触发和异步任务另计。一次正常完整运行可结束基线；异常优先复现；额外投入较长仍不能判断时写“待定位”及缺什么证据，不反复盲试。

本轮完成标准是：每个已执行任务有完整记录与可核对结论，未执行说明原因；候选缺陷有复现和影响依据；没有把方案写成发现。并不要求跑完24个才能交报告。

## 九 总结报告与决赛积累

初赛报告按[老师报告模板](../老师模板/测试报告模板.md)原字段组织，通常一份持续编辑。探索范围、深挖代表案例、跨案例规律、方法论、隐私安全等按必填性保留；跨案例规律至少依据两个已提交案例，未达到时如实写证据不足，不能用待测计划或本地编号冒充。统计分清任务数、有效执行次数、候选数、问题簇和真实已提交数，不把截图张数当复现次数。

改进建议应对应证据。例如“提醒改期时保留对象ID并复核旧时间已取消”可作为产品建议；不要在无日志时断言“数据库写锁失效”。

为决赛保存完整脱敏多轮文本、入口、主场景、实际等级、有效性说明、归因和证据索引。可逐步积累指南建议的30—50条小样本；数量是准备建议，不能凭空补标签或伪造会话。届时验证准确率、宏平均F1、Cohen’s Kappa、混淆矩阵，重点检查A档/正确拒答误报及C/D分界。相同问题的近似变体做训练/验证划分时应同组，避免泄漏。初赛探索样本经过有意筛选，不能代表线上真实失败率。
