## CRT01 局部编辑撤回后未指定区域也变化

**入口：** 图片入口或主入口传图

**准备：** 合成基准图为白底，左红方块、中蓝圆、右绿三角，底部黑字P7；保留原图逐版对比。

**执行顺序：** P2。**观察机制：** 局部编辑范围与撤回版本。

**逐轮执行：**

1. 【手动操作后发送消息】上传基准图：只把左侧红方块改成黄色，其他形状、位置、尺寸、白底和P7保持。
2. 【发送消息】在这一版上只给黄色方块加细黑边，其他不要重画。
3. 【发送消息】只把黑边变细一点，黄色和其他区域保持。
4. 【发送消息】撤回黑边，保留黄色，不要恢复成红色，也不要改其他区域。
5. 【手动操作】打开最终图片并与原图、首轮黄色版对比，记录真实变化区域；没有图时记录是否仍处理中或明确失败。

**核对答案或正确行为：** 最终仅原红方块变黄色；黑边已撤回，蓝圆、绿三角、P7和布局保持。

**失败信号：** 撤回范围过大恢复红色；多轮全图重绘导致其他对象或文字变化；版本引用错误。

**判级边界：** 实质局部约束丢失一般C，不因背景变化直接D；只有明确完成承诺且无产出等红线另审。

**复现与对照：** 直接一轮修改与四轮编辑对照；目标改到右侧对象。与原局部改图类合并同根因。

**素材：** `测试素材/六类能力/局部编辑基准.png`

**与原30例的关联：** OPT-013、OPT-017（局部编辑对照，不重复计类）。若实测为同一机制，合并记录，不因换入口或题材重复报送。

## CRT02 柱状图负值零值与重排序不一致

**入口：** 主入口图表生成

**准备：** 支持可核对的图表产出；使用甲12、乙0、丙−4、丁8四个合成数值。

**执行顺序：** P1。**观察机制：** 有符号数可视编码与排序绑定。

**逐轮执行：**

1. 【发送消息】生成柱状图：甲12、乙0、丙−4、丁8，展示每个原始数值。
2. 【发送消息】保留横向零基线，负值在零线下，乙即使为0也要显示类别和数值标签。
3. 【发送消息】按数值从小到大排，不按绝对值；不要变动数据。
4. 【发送消息】只把丁从8改成−2，并按原规则重新排序。
5. 【手动查看后发送消息】打开最终图，核对顺序和柱高；再请求附最终数据表，与图逐项对应。

**核对答案或正确行为：** 最终顺序丙−4、丁−2、乙0、甲12；负值方向正确，零值未丢失；图和表一致。

**失败信号：** 漏掉零值；负数画成正数；绝对值排序；柱高与标签错位；丁仍使用8。

**判级边界：** 使数据表达实质失真通常C；样式偏好不是缺陷，普通绘图错误不自动D。

**复现与对照：** 柱状转条形；交换输入顺序；加入相等数值；全负数对照。

## CRT03 预算饼图偷偷改变占比分母

**入口：** 主入口图表生成

**准备：** 合成预算总额100元；餐饮30、交通20、门票10，其余未分配。

**执行顺序：** P1。**观察机制：** 部分总体分母与余额约束。

**逐轮执行：**

1. 【发送消息】总预算100元，餐饮30、交通20、门票10，剩余未分配，生成预算占比饼图。
2. 【发送消息】包含未分配部分，以总预算100为分母，不把三个已分配项目重新归一化成100%。
3. 【发送消息】只把餐饮从30改成40，总预算仍100，其他已分配项目不变。
4. 【发送消息】每块同时标金额及占总预算百分比。
5. 【手动操作】查看实际图和图例，核对四部分金额、比例及未分配余额，而非只核对回复文字。

**核对答案或正确行为：** 初始未分配40元；修改后餐饮40、交通20、门票10、未分配30，比例40%、20%、10%、30%。

**失败信号：** 漏未分配；改用70为分母；图形比例与标签矛盾；餐饮更新而余额未更新。

**判级边界：** 明确分母后仍产生实质误导图表一般C；正常询问总额或指出超预算是正确表现。

**复现与对照：** 饼图转环图；总预算改200但已分配金额不变；先表后图与直接生图对照。

## CRT04 PDF重排版后末条丢失或特殊字符损坏

**入口：** 主入口PDF生成

**准备：** 版本明确支持文件生成；全部正文为下列合成测试记录，无真实隐私。

**执行顺序：** P1。**观察机制：** 导出排版完整性与字符保真。

**逐轮执行：**

1. 【发送消息】把12条记录完整生成PDF，标题‘合成数据测试’，不总结、不删行。
2. 【发送消息】记录：01甲12元；02乙0元；03丙−4元；04温度36.5℃；05编码001；06公式a≤b；07中文引号‘测试’；08地址东门；09截止2027-06-03；10数量3；11备注无；12结束标记END-12。
3. 【手动操作】打开第一版PDF，确认12条和末尾标记实际存在，保存第一版用于对照。
4. 【发送消息】在这版基础上把正文字号调大并重新分页，内容一个字也不要删，保留每条完整编号。
5. 【手动操作】下载并打开修订PDF逐页核对，尤其检查末页、END-12、001、负号、℃、≤，记录文件是否真实可用。

**核对答案或正确行为：** 修订PDF仍含全部12条；特殊字符与数字不变，末条可见，不出现裁切或坏文件。

**失败信号：** 字号调整导致末页遗漏；乱码；前导零丢失；内容越界；下载得到空文件或旧版。

**判级边界：** 实质缺字、乱码、分页裁切通常C；明确称已交付PDF却不存在文件且排除加载问题，另审D档虚假完成。

**复现与对照：** 不同字号与长行；先生成再改标题；比较客户端预览与下载文件，区分预览问题。

**与原30例的关联：** OPT-009（文件可用性相关；本例重点为已生成文件重排版完整性）。若实测为同一机制，合并记录，不因换入口或题材重复报送。

## CRT05 流程图局部修改导致其他分支误接

**入口：** 主入口流程图生成

**准备：** 支持实际流程图，不以纯文字复述替代已要求的图；如能力未开放先记录限制。

**执行顺序：** P1。**观察机制：** 图拓扑局部变更与边绑定。

**逐轮执行：**

1. 【发送消息】画流程图：开始→填写表单→检查完整性；不完整返回填写，完整进入预览→结束。
2. 【发送消息】检查完整性的两条分支明确标‘完整’与‘不完整’，每个箭头方向清楚。
3. 【发送消息】在预览后加入用户确认；确认后结束，拒绝确认则返回填写。
4. 【发送消息】只把拒绝确认改为返回预览，完整性检查的不完整分支仍返回填写，其他连线不变。
5. 【手动查看后发送消息】打开最终图逐一看箭头；请求列出所有连线，与图对照，不只相信解释。

**核对答案或正确行为：** 完整性不完整→填写，完整→预览→用户确认；拒绝确认→预览，确认→结束；无孤立节点或错误回路。

**失败信号：** 改一个分支连带改另一个；箭头方向反；标签悬空；文字解释正确而图错误。

**判级边界：** 流程核心逻辑错误一般C；表现形式不同但逻辑等价不算错。无红线不直接判D。

**复现与对照：** 纵向改横向；节点重排；两次局部修改；保留每版图定位首次误接轮次。

## CRT06 合成对话图卡重排后角色消息归属错乱

**入口：** 主入口对话图卡生成

**准备：** 只用虚构甲乙，图上保留合成示例标识，不冒充真实聊天、不对外发布。

**执行顺序：** P1。**观察机制：** 视觉排版中的说话人语义绑定。

**逐轮执行：**

1. 【发送消息】生成标注‘合成示例’的对话图卡，甲固定在左，乙固定在右。
2. 【发送消息】严格四条依次为：甲‘预算100’、乙‘收到’、甲‘改成120’、乙‘按120处理’，不增删其他话。
3. 【发送消息】只将第二条‘收到’改为‘已记录’，其余三条与角色不变。
4. 【发送消息】整体改成浅色主题，消息顺序、左右归属和合成示例标识保持。
5. 【手动操作】打开最终图逐条核对四条消息及角色，重点比较文字说明与图中实际内容是否一致。

**核对答案或正确行为：** 四条消息不增不减，归属与顺序准确；第二条已记录；主题变化不改变100/120及合成标识。

**失败信号：** 左右角色交换；漏消息；预算值串位；第二条改错；重排后删除合成标识。

**判级边界：** 图中语义、归属或数据实质错误一般C；仅外观不符合偏好不判Bad Case。

**复现与对照：** 同一角色连续两条；数字短消息；主题和字号修改前后对照。

## CRT07 拼图单张替换后保留旧图或重排顺序

**入口：** 图片编辑入口或主入口多图上传

**准备：** 准备红底A、黄底A、蓝底B、绿底C四张合成卡片；初始只上传红A、蓝B、绿C，黄色A在替换轮上传。

**执行顺序：** P1。**观察机制：** 多图对象身份与替换映射。

**逐轮执行：**

1. 【手动上传后发送消息】上传红A、蓝B、绿C：横向拼接，顺序必须B、A、C，不裁字母。
2. 【发送消息】每张等宽，图间白色间隔相同，保持B、A、C顺序。
3. 【手动上传后发送消息】上传黄A：只用新黄A替换中间红A，蓝B和绿C不变，最终仍只有三张。
4. 【发送消息】改竖向，从上到下仍B、A、C，黄色A不要退回红色。
5. 【手动操作】查看最终图，逐一核对蓝B、黄A、绿C、数量三张及字母不裁切。

**核对答案或正确行为：** 三图最终竖向蓝B、黄A、绿C，无旧红A，无新增重复卡片。

**失败信号：** 按上传顺序重排；替错图；旧红A重复保留；横转竖后恢复旧素材；裁切字母。

**判级边界：** 主体对象、顺序或版本错误通常C；请求澄清哪张是A可合理，不应强判差。

**复现与对照：** 改变上传顺序；相同文件名不同颜色；只用一次直接最终要求作对照。若同源指代错误则与原图选择案例归类合并。

**素材：** `测试素材/六类能力/卡片_A红.png`；`测试素材/六类能力/卡片_A黄.png`；`测试素材/六类能力/卡片_B蓝.png`；`测试素材/六类能力/卡片_C绿.png`

**与原30例的关联：** OPT-015（多图指代相关；新增实际替换与拼接版本核对）。若实测为同一机制，合并记录，不因换入口或题材重复报送。

## CRT08 收藏笔记编辑被当成新建或改错笔记

**入口：** 主入口与收藏笔记实际列表

**准备：** 指定版本支持创建和管理收藏笔记。只用本人合成测试笔记；测试后清理，不在其他真实笔记上操作。

**执行顺序：** P1。**观察机制：** 创建与更新语义及目标笔记身份。

**逐轮执行：**

1. 【发送消息并按需确认】创建测试笔记‘测试清单A’，正文水、面包，标签测试。
2. 【发送消息并按需确认】再创建‘测试清单B’，正文电池，不要合并；随后手动到列表确认已有两条。
3. 【发送消息】只修改测试清单A：去掉面包，加雨伞，标题和标签不变，B不要动。
4. 【发送消息】给测试清单A加一句‘完成后核对’，更新现有笔记，不要新建。
5. 【手动操作】打开实际笔记列表，核对总数和两条正文、标签；保存证据后清理测试笔记。

**核对答案或正确行为：** 仍两条；A含水、雨伞、完成后核对，保留标题标签；B仍仅电池。

**失败信号：** 修改另建副本；A旧项目复活；B被改；标签丢失；回复成功但列表不存在变更。

**判级边界：** 编辑寻址或重复新建影响任务通常C；明确声称已保存但实际未执行，排除确认和同步问题后另审D。

**复现与对照：** 相似标题；先改标题再改正文；退出重开查实际保存；避免仅凭聊天复述作为操作证据。

## CRT09 图表换主题后图例颜色和数据系列错位

**入口：** 主入口折线图生成

**准备：** 使用固定合成三天数据：计划2、4、6；实际1、5、3。

**执行顺序：** P1。**观察机制：** 视觉样式与数据系列绑定。

**逐轮执行：**

1. 【发送消息】画两组折线：第1、2、3天计划2、4、6；实际1、5、3，数据点有清楚标记。
2. 【发送消息】计划固定蓝色虚线，实际固定橙色实线，图例准确。
3. 【发送消息】背景换深色，提高文字对比度，数据和颜色对应关系不变。
4. 【发送消息】只把实际第3天从3改成7，再标注实际第2天5与第3天7。
5. 【手动查看后发送消息】查看最终图中线型、图例、点位和标注；请求附最终数据表逐项核对。

**核对答案或正确行为：** 蓝虚线始终计划2、4、6；橙实线始终实际1、5、7；实际第2天5、第3天7与图例对应。

**失败信号：** 换主题交换图例含义；改错系列；标签仍是旧值3；数据表正确而图错。

**判级边界：** 语义映射或数值表达失真一般C；不凭配色审美判差，无红线不直接D。

**复现与对照：** 移动图例；连续换两次主题；交换输入系列顺序；核对折线交叉位置。

## CRT10 跨表格图表PDF修订时只更新部分产物

**入口：** 主入口串联图表与PDF生成

**准备：** 指定版本支持图表和PDF，使用合成预算。保存旧版文件便于区分缓存和真实修订。

**执行顺序：** P0。**观察机制：** 多产物依赖更新与导出版本一致性。

**逐轮执行：**

1. 【发送消息】做预算表：餐饮40、交通20、门票10、未分配30，总计100，原数值不得自行调整。
2. 【发送消息】基于这张表生成柱状图，并把表和图放进同一份PDF，提供文件。
