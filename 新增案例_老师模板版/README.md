## 建议先做

先按实际需求选A05、A06、C05、D05、E05；它们已备文本或图片，无需真实联系人、支付或消息发送。B05/B06需要核对真实聊天入口与选区；F05/F06必须进入真实生成工具并手动操作。P0共5项、P1共7项，是个人执行顺序，不是问题严重度。

1. 打开单例执行脚本，确认需求对自己有用，检查指定版本与输入条件。只把当前步骤的话术和素材提供给小微，核对答案留给自己。
2. 保存完整会话和真实操作。合理澄清可继续；发生意外外部动作时先停止并保留状态。此方案不授权自动发送、发布、报名、支付或压测。
3. 根据实测选择Bad或Good待填稿，复制到本地`实测记录/`后填写。不要在可公开的方案文件里写入原始私密证据。
4. Bad记录问题出现次数；Good记录无需错误纠正的一次办成次数。用户正常追加需求不等于纠错，一轮消息也不等于一次独立测试。
5. 发现差异后做同条件复现，再做单变量对照。合理拒答、未开放入口、正常耗时先排除；产品卡住仍如实记录，不筛掉失败尝试。
